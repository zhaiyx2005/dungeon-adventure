## 二、🔴 为什么必须重采样到"显示尺寸的原生网格"

AI 出的是"看起来像像素画"的插画：像素块在 1536 宽的原图里是 ~16px。
直接把原图缩到卡面图片区（**实测 96×75**），等于把 128 个色块映射到 84 个显示像素
—— **像素块被抹平，像素感直接消失**，只剩一张小糊图。

所以要先降到"和显示尺寸同量级"的原生网格，再限色板：

| 类型 | 目标网格 | 依据 |
|---|---|---|
| 卡面 `card` | **96×75** | 城镇战斗卡 / 卡牌大全图片区的实测尺寸（手牌是 84×66，接近 1:1） |
| 物品 `item` | **100×68** | 人物卡图片区实测（归一化 0.107–0.891 × 0.130–0.508 落在 128×179 上） |
| 单位 `unit` | **96×96** | 战斗单位立绘带 128×88 |
| 背景 `bg` | **1280×720** | 逻辑分辨率本身 —— **背景是唯一的例外，不缩到像素网格** |

**物品这一档必须与显示尺寸**完全**一致**，不能"差不多就行"：
`CardFrame._art_image` 是 `KEEP_ASPECT_COVERED`，**比例不符就会裁掉边角** ——
卡面插画被裁掉一角无所谓（它本来就带背景），但剑 / 弓 / 甲被裁掉一头一尾就废了。
所以物品走 `fit_contain`（等比缩到完整装进画布、居中留透明边），不是 `fit_cover`。

**背景反过来：不要缩到像素网格。** 它是给人"看氛围"的铺底图，
缩成 320×180 再放大 4 倍会变成一堵花花绿绿的墙，和 1:1 显示的小 UI 文字严重打架。
保持 1280×720 + 96 色板即可；显示时用 `LINEAR_WITH_MIPMAPS` 而不是 NEAREST。

重采样用 **BOX（面积平均）**，这是"像素化"的正确滤波器；
再用 `quantize(MEDIANCUT, dither=NONE)` 限色，恢复受限调色板的观感。

**显示端必须配 `TEXTURE_FILTER_NEAREST`**（`CardFrame._art_image` / `UnitView._art`），
线性插值会把 96px 的像素块糊掉。（背景是例外，见上。）

## 三、🔴 抠底的五个坑（都实测踩过）

### 坑 1：全局颜色阈值会在画面边缘留下不透明的边

背景常常是**带暗角/渐变**的。按"洋红程度 = min(R-G, B-G)"全局判定，
暗角处洋红程度掉到阈值以下 → 判成不透明 → **画面左边和底边各留一条黑边**。

**必须从四条边界向内洪泛**（BFS），并且两个条件缺一不可：
* 邻居本身仍属背景色系 —— 主体深色轮廓天然挡住扩散
* 邻居与当前像素的单通道差 ≤ `LOCAL_TOL` —— 允许背景渐变，但拦住跨到主体上

顺带的好处：主体内部与背景同色的像素（白袍、白云）不会被误抠，因为洪泛进不去。

### 坑 2：`key=auto` 的容差必须大于"投影离底色的距离"

用户给的图（豆包）是**奶油底 `#FFFAC0`**，且脚下有一块**中棕色投影 `#CC9054`**。

第一版容差上限 82（< 投影的 108）的后果：
投影挡住洪泛 → **两腿之间那块被围住的奶油底永远抠不掉**（成了孤岛），
脚下还留一大块投影。修正：`AUTO_BORDER_CAP` 提到 **126**、
`AUTO_LOCAL_TOL` 提到 **56**（奶油→投影的单步差是 51）。

**上限不能再高**：主体橙色外衣离底色 132，再往上就啃到衣服。

### 坑 3：投影**不是**"底色 × k"

原本想用 `c ≈ base * k` 的残差判据剔投影，实测只命中 0.4%。
采样后看清：投影 `#CC9054` 的 G/B 比 R 压得多（k≈0.63 但残差 43），不是纯乘性压暗。
**判别只能靠几何洪泛（坑 2 的容差），残差只能当兜底。**

### 坑 4：模型偶尔不听"纯洋红底"的指示

实测 `goblin_chief` 出成了**白底**。白色 R=G=B → 洋红程度 0 → 连洪泛种子都取不到
→ 93.8% 的像素保持不透明，整张图带着白底进游戏。

修正：`key_background_smart()` —— 洋红模式覆盖率 < 35% 就**自动改用 `auto` 重试**，
覆盖更多就用 `auto` 的结果。这样"模型听不听话"不再影响管线，不需要人工挑出坏图。

> **排查手法**：立绘的"不透明像素占比"中位数是 ~35%。
> 明显高于 60%（尤其 > 85%）就是底色没抠掉；配合"不透明像素均色接近白/纯色"一起看。

### 坑 5：🔴 闭合成环的物体，环内的背景抠不掉（必须补一道严格色阈）

洪泛只能从画布边界向内走。**弓（弓臂 + 弓弦闭合成环）、吊坠、王冠、护符**这类物体
中间的背景被主体轮廓**围死**，从边界根本走不到 → 那块洋红原样留在成品里，
贴到深色卡面上像一块污渍。实测踩了 5 张：`short_bow` / `storm_bow` /
`silver_pendant` / `victory_crown` / `wooden_charm`。

修正：洪泛之后再补一道 **`_kill_magenta_residual()`** —— 对"洪泛没覆盖到、
颜色仍接近纯洋红（`min(R-G, B-G) ≥ HARD_MAGENTA=100`）"的像素一律判为背景。

> ⚠️ **不要**用"从边界沿非背景像素能否走到"来判孤岛。主体常常贴着画布边缘，
> 孤岛经主体 4 邻域就能连到边界，会被误判成"可达"——
> `victory_crown` 就是这么漏掉的（第一版这么写，残渣 632 像素没清掉）。

> ⚠️ 这道严格色阈**只给洋红模式用**。洋红是提示词里的标记色，真实主体不会用
> 接近纯洋红 (255,0,255) 的颜色，所以不会误伤；而 `auto` 模式的底色是
> "图里本来就有的颜色"（例：奶油底），主体内部完全可能有同色块（例：米色长袍），
> 全局阈值会在袍子上打洞 —— 那边保持"洪泛 + 投影剔除"，不加这一道。

## 四、其它两个坑

* **先裁到主体再缩放**。用户图主体只占画面 36% 宽（2304×1728 的图里主体 823×1313），
  不裁就等于把 2/3 的分辨率扔在透明边上。裁完再 fit，主体能多拿 ~30% 的有效像素。
* **预览图 `paste` 不带 mask 会忽略 alpha**。把透明 PNG 直接 `sheet.paste(im, box)`
  会把透明区当暗色贴上去 → 看起来像"抠图失败"，其实素材是好的。
  正确做法：先铺棋盘 → `board.paste(im, (0,0), im)` 用 alpha 合成 → 再贴到图上。

## 五、怎么验"抠底没啃到角色"

不能靠肉眼。用**数值基准**：

```python
# 真主体 = 离底色 > 130 的像素（投影 108、奶油 0 都被排除）
bbox = 真主体包围盒 ; ratio_src = bbox.w / bbox.h
# 成品 = alpha 通道的包围盒
ratio_out = out.getbbox().w / out.getbbox().h
# 两者应几乎相等
```

实测：hero 0.494 vs 0.500、hero_battle 0.462 vs 0.466 → 误差 <1.3%，确认轮廓完整。

## 七、运行时取用规则（`scripts/ui/art_registry.gd`）

```
ArtRegistry.card(id)            → 卡面插画（96×75）
ArtRegistry.item(id)            → 物品图标（100×68, RGBA, 透明底）
ArtRegistry.unit(id)            → 立绘原图（96×96, RGBA）
ArtRegistry.unit_bust(id,0.64)  → 半身像（人物卡用）
                                   ⚠️ 只对人形用，四足怪取上部只剩后背
ArtRegistry.unit_trimmed(id)    → 按 alpha 裁掉透明边（整身塞进立绘带）
ArtRegistry.unit_battle(id)     → 优先 <id>_battle.png，否则 unit_trimmed(id)
ArtRegistry.monster_battle(m)   → 怪物战斗立绘
ArtRegistry.adventurer_bust(a)  → 先 a.id，没有则按职业原型
ArtRegistry.adventurer_battle(a)→ 先 a.id / a.id_battle，没有则按职业原型
ArtRegistry.has_card/item/unit(id) → 素材是否存在
```

**全部取用点都允许返回 `null`**：`CardFrame` 拿到 null 就回落到占位色块，
所以"只出了一部分素材"和"全量出完"两种情况都能正常跑。

### 职业原型派发（招募池）

招募池里的冒险者是**随机属性 + 随机名**生成的（`TownManager.roll_recruit`），
**没有固定身份**，不可能给每个 id 都出立绘。所以按"最高属性"分派：

| 最高属性 | 原型 |
|---|---|
| 力量 | `warrior` 佣兵 |
| 智力 | `arch_scholar` 学者 |
| 精力 | `arch_rogue` 盗贼 |
| 体质 | `arch_priest` 牧师 |
| **最高值并列 + 极差 ≤1** | `arch_ranger` 游侠（万金油） |

⚠️ "平均"的判据必须是**并列 + 极差 ≤1**，只写"极差 ≤1"会把 5/5/6/5 这种
"智力唯一最高"也判成游侠（实测踩过）。

## 八、卡面与代码的分工（重要）

**插画一律不含任何文字**，六分类文字与它的实底药丸由**代码**画在插画之上。

原因：胶囊里的字来自数据（物理进攻 / 法术特殊 / 共鸣 / 联合 …），
AI 生成图里的中文完全不可控，而且每张卡不同。

实现：`CardFrame` 里 `_tag_bg`（实底 Panel）+ `_art_tag`（Label）都画在 `_art_clip` **之后**，
所以叠序是 **插画 < 实底药丸 < 类型字**。

> ⚠️ 边框贴图里本来画了一个白色药丸，但它在图片层**下面**；
> 插画铺到 0.600（胶囊底）后会把那个白药丸盖住，只剩深灰字直接压在插画上 ——
> 深色插画上完全读不出来。所以有插画时必须自己补一块实底。

**几何**：`BATTLE_ZONE.art` 在**有插画**时扩到 `[0.126, 0.182, 0.874, 0.600]`，
胶囊两侧的色块补角（`_art_wing_l/r`）相应隐藏。

### 物品卡的文字预算（🔴 卡面文案的硬约束）

物品卡是 `person` 版式，描述框 **89×55px**，8px 字最多 **4 行**。
一段物品文案 = 首行（稀有度 · 部位）+ 属性行 + 描述，所以：

```
首行 1 行 + 属性 1 行 + 描述 ≤2 行   →   合计 ≤4 行
```

**属性行必须只占 1 行**——三条加成时用双空格分隔就会到 2 行，
加上首行 + 描述 2 行正好 5 行，**最后一行被静默吃掉**。
实测 6 件三加成装备（碎界 `world_breaker`、龙鳞甲 `dragon_scale`、命运之眼 `eye_of_fate`、
战王之刃 `warlord_blade`、奥术法袍 `arcane_vestment`、智慧之冠 `crown_of_wisdom`）
全是这个症状。

修法：`ItemData.get_bonus_text_cn()` 的分隔符**只用单个半角空格**（`" ".join`）。

**防回归**：卡面文案统一走 `ItemData.get_card_desc_cn()`，
`scripts/_probe_descfit.gd`（文字预算探针）复用**同一个方法**逐张量。
探针自己再拼一份文案一定会漂移 —— 那时"改了文案被截断"照样漏检。

> 探针按"卡面真实会出现的尺寸"逐档量：物品卡在任何界面都是 128×179
> （`town_scene._item_card` 写死 `custom_minimum_size`），
> 手牌 112×157 / 卡组 120×162 只用于战斗卡牌 ——
> 拿那两个尺寸量物品只会产出假告警，把真问题淹掉。

## 九、提示词：风格块只写一份

`tools/make_art_prompt.py` 里的 `STYLE` 常量：

```
16-bit pixel art {noun} in classic JRPG style, vivid saturated colors,
clean flat color areas with 3-tone shading, crisp 1-pixel dark outline,
no dithering, no texture noise, bright cheerful palette
```

**9-26 定稿，不要再加回 `dark fantasy / atmospheric haze / dramatic rim lighting`。**
第一版写了那三个词，出来的主体饱和度只有 **0.23–0.35**；
用户参考图（豆包的主角）是 **0.85**。并列像两个游戏，只能全部重出。

主体描述放 `tools/art_prompts.json`（id → 英文主体描述），
风格与主体解耦：改风格不用逐条改提示词。

### 三类各自的收尾块

```python
CARD_TAIL =  "Centered composition filling the frame, simple dark stone background …"
ITEM_TAIL =  "The object lies diagonally across the frame at a three-quarter angle, filling
              most of the frame, a single object, … no character, no hands, no person,
              not worn, no cast shadow, no ground, no scenery. …"
UNIT_TAIL =  "Full body, centered, isolated on a flat solid pure magenta background …"
```

物品块有两个必须写的点：

* **斜置 + 铺满画面**。物品卡的图片区是横向的（1.47:1），竖着摆的剑缩进
  `fit_contain` 会又细又小；斜置后主体包围盒接近横向，才能拿满可用空间。
  （结果：67 件的成品主体框宽度 36–92px，高度统一 61–65px。）
* **显式排除"人 / 手 / 穿戴"**。不写的话模型很容易画成一个拿着剑的角色。

### 场景背景的收尾块（`bg`）

```
BG_TAIL = "Wide establishing shot, full-bleed background art.
           No characters, no people, no creatures, no text, no letters, no numbers,
           no watermark, no logo, no frame, no border, no UI overlay, no HUD.
           Composition calm and uncluttered in the centre so interface elements
           stay readable on top of it."
```

三个点都不能省：

* **不要角色**（`no characters / no people / no creatures`）—— 否则会有人物盯着你看，
  而且和界面上的立绘、卡面打架。
* **中心别太花**（`calm and uncluttered in the centre`）—— 深色文字压在浅色 scrim 上，
  底图太闹就读不出来（见 `数值设计_v2.0.md` §11.7）。
* **明确"全幅铺底"**（`full-bleed background art`）—— 不然容易出一张带边框的"画"。

## 十一、已知限制

* **各单位的像素密度不统一**：AI 让每只怪都填满画布，所以野猪（宽）与巫王（高）
  在立绘带里都会被 fit 到同一高度，实际体型关系丢失。要修得让提示词带
  "角色实际身高参照"（例如统一以人形身高为基准），或手工标定缩放。
* **原型立绘会被多个招募者复用**（同一原型的人长得一样）。要区分得给招募池
  定义固定角色表 —— 属设计改动。
* **物品图标的"体量关系"是丢失的**：`fit_contain` 让每件都填满可用空间，
  所以短剑和碎界在卡面上看着一样大（和单位立绘是同一个问题）。
  这对"图标"其实是好事（尺寸统一、不跳），但如果想让碎界明显更"重"，
  得手工标定缩放系数或按 tress 稀有度给一个缩放区间。
* 卡面插画是**带背景的插画**（暗色石刻背景），物品 / 立绘是**透明底**，
  三种视觉语言并存：卡面贴深色卡框、物品贴人物卡的浅色图片区、立绘贴深色立绘带。
