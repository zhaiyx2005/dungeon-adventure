# 《地牢冒险记》数据字段规范 v1.0

> **用途**：这是"专项任务"的施工图。任何负责卡牌 / 怪物 / 关卡的任务，只准按本规范往自己目录里写文件。
> **配套**：`docs/设计草案_v0.3.md`（框架）、`docs/数值设计_v1.0.md`（数值）
> **格式**：Godot 4 的 `.tres` Resource 文件（也可用 JSON，见第七节）

---

## 零、给专项任务的硬性约束

**做卡牌的：只往 `res://data/cards/` 写文件，不要碰 `scripts/`。**
**做怪物的：只往 `res://data/monsters/` 写文件，不要碰 `scripts/`。**
**做关卡的：只往 `res://data/dungeons/` 写文件，不要碰 `scripts/`。**

违反这条，并行开发就会互相覆盖。字段拿不准时**不要自己加字段**，回来问。

---

## 一、命名与 ID 规则

| 项 | 规则 | 示例 |
|---|---|---|
| 文件名 | 小写下划线 | `fireball.tres` |
| ID | 与文件名同名（不含扩展名） | `fireball` |
| 中文名 | `display_name` 字段 | `"烈焰术"` |
| 分类枚举 | 全大写下划线 | `ATTACK` / `DEFENSE` / `SPECIAL` |

> ID 一旦确定**不可更改**（存档、卡组、存档引用都会失效）。

## 二、战斗卡牌 `data/cards/*.tres`

### 2.1 字段表

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | String | ✅ | 唯一标识，同文件名 |
| `display_name` | String | ✅ | 中文显示名 |
| `description` | String | ✅ | 卡面描述文本 |
| `card_class` | Enum | ✅ | `ATTACK` / `DEFENSE` / `SPECIAL` |
| `damage_type` | Enum | ✅ | `PHYSICAL` / `MAGICAL` / `NONE` |
| `multiplier` | float | ⬜ | 伤害倍率（攻击卡必填） |
| `shield_multiplier` | float | ⬜ | 护盾倍率（防御卡必填） |
| `heal_multiplier` | float | ⬜ | 治疗倍率（治愈类必填） |
| `action_cost` | int | ✅ | 消耗行动值 |
| `mana_cost` | int | ✅ | 消耗蓝量（0 表示不消耗） |
| `target_type` | Enum | ✅ | `SINGLE_ALLY` / `SINGLE_ENEMY` / `ALL_ENEMIES` / `ALL_ALLIES` / `SELF` / `FIELD` |
| `rarity` | Enum | ✅ | `COMMON` / `RARE` / `EPIC` / `LEGENDARY` |
| `effect_tags` | Array[String] | ⬜ | 附加效果标签，如 `["REVIVE"]` |
| `art_placeholder` | String | ✅ | 占位色，如 `"#D85A30"`（美术阶段用） |

### 2.2 枚举定义

```
card_class:   ATTACK | DEFENSE | SPECIAL
damage_type:  PHYSICAL | MAGICAL | NONE
target_type:  SINGLE_ALLY | SINGLE_ENEMY | ALL_ENEMIES | ALL_ALLIES | SELF | FIELD
rarity:       COMMON | RARE | EPIC | LEGENDARY
effect_tags:  REVIVE | BUFF_ACTION | DEBUFF_DEFENSE | DRAW | HEAL_OVER_TIME
```

## 三、怪物 `data/monsters/*.tres`

### 3.1 字段表

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | String | ✅ | 唯一标识 |
| `display_name` | String | ✅ | 中文名 |
| `description` | String | ⬜ | 描述 / 图鉴文本 |
| `hp` | int | ✅ | 血量 |
| `phys_atk` | int | ✅ | 物攻 |
| `mag_atk` | int | ✅ | 法攻 |
| `phys_res` | int | ✅ | 物抗 |
| `mag_res` | int | ✅ | 法抗 |
| `technique` | int | ✅ | 技巧 / 暴击值 |
| `power` | float | ⬜ | 战力（留空由引擎算） |
| `monster_tier` | Enum | ✅ | `NORMAL` / `ELITE` / `BOSS` |
| `dungeon_level` | int | ✅ | 所属层级（1 起） |
| `ai_pattern` | Enum | ✅ | `AGGRESSIVE` / `RANDOM` / `DEFENSIVE` |
| `drop_table` | String | ⬜ | 掉落表 ID |
| `art_placeholder` | String | ✅ | 占位色 |

### 3.2 战力自动计算

```
power = hp × 0.5 + (phys_atk + mag_atk) × 1.5
      + (phys_res + mag_res) × 1.0 + technique × 2.0
```

**不要手填 `power`**，留空由引擎计算，避免手算错误导致战力与数值不一致。

## 四、关卡 / 地牢 `data/dungeons/*.tres`

### 4.1 字段表

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | String | ✅ | 唯一标识 |
| `display_name` | String | ✅ | 层级名，如"新手地穴" |

| `recommend_power_min` | int | ✅ | 推荐总战力下限（准入用） |

| `entry_cost` | int | ✅ | 直接进入的金币费用 |

| `node_weight_treasure` | int | ✅ | 宝箱权重 |
| `node_weight_event` | int | ✅ | 事件权重 |
| `monster_pool` | Array[String] | ✅ | 本层可出现怪物 ID 列表 |
| `elite_pool` | Array[String] | ⬜ | 精英怪 ID 列表 |

## 六、物品卡牌 `data/items/*.tres`

### 6.1 字段表

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | String | 唯一标识 |
| `display_name` | String | 中文名 |
| `description` | String | 描述 |
| `item_class` | Enum | `EQUIPMENT` / `CONSUMABLE` / `COLLECTIBLE` / `TROPHY` / `JUNK` |
| `slot` | Enum | 装备槽（非装备填 `NONE`） |
| `stats_bonus` | Dictionary | 数值加成，如 `{"phys_atk": 5, "hp": 20}` |
| `precious_value` | int | 珍贵值 0–100（决定颜色） |
| `sell_price` | int | 售价 |
| `usable_in_battle` | bool | 能否战斗中从背包使用 |
| `art_placeholder` | String | 占位色 |

> **注意**：`stats_bonus` 的 key 使用**一级属性名**（`hp` / `mana` / `action` / `phys_atk` / `mag_atk` / `phys_res` / `mag_res` / `technique` / `luck`），直接用数值相加，不参与属性换算公式。

**物品类别枚举数字对照**：

| 枚举 | 值 |
|---|---|
| `item_class`: EQUIPMENT/CONSUMABLE/COLLECTIBLE/TROPHY/JUNK | 0 / 1 / 2 / 3 / 4 |

**装备槽枚举数字对照**：

| 枚举 | 值 |
|---|---|
| `slot`: HEAD/NECK/BODY/HAND/LEG/FOOT | 0 / 1 / 2 / 3 / 4 / 5 |
| `slot`: WEAPON_1H/WEAPON_2H/WEAPON_RANGED/NONE | 6 / 7 / 8 / 9 |

**装备槽枚举**：
`HEAD / NECK / BODY / HAND / LEG / FOOT / WEAPON_1H / WEAPON_2H / WEAPON_RANGED / NONE`

**珍贵度颜色区间**（由 `precious_value` 决定）：

| 颜色 | 区间 |
|---|---|
| 白 | 0–10 |
| 绿 | 11–25 |
| 蓝 | 26–45 |
| 紫 | 46–70 |
| 金 | 71–90 |
| 红 | 91–100 |

> 物品卡牌的**枚举值对照表见第六节**（`item_class` 与 `slot`）。

### 6.2 批量生成脚本

所有 `data/` 下的资源由 `tools/generate_data.py` 统一生成。**改数值请改脚本里的数据表，不要手改 .tres** —— 否则下次跑脚本会被覆盖。

```
python tools/generate_data.py
```

脚本会：
1. 生成 `data/cards/`、`data/items/`、`data/monsters/`、`data/dungeons/` 全部资源
2. 打印各类别数量统计
3. **交叉校验**：检查每个关卡引用的 `monster_pool` / `elite_pool` / `boss_id` 是否真实存在于怪物表

在真实 Godot 工程中，`tools/` 应放在**项目根目录之外**（或用 `.gdignore` 排除），避免 Godot 尝试导入 Python 文件。

## 七、目录结构（最终）

```
res://
├── data/
│   ├── schema/          ← 单点独占：字段定义、校验规则
│   ├── cards/           ← 卡牌任务独占
│   ├── monsters/        ← 怪物任务独占
│   ├── dungeons/        ← 关卡任务独占
│   ├── items/           ← 物品任务独占（可与卡牌合并）
│   └── drops/           ← 掉落表
└── scripts/
    └── core/            ← 单点独占：战斗引擎、数据加载、校验脚本
```

---

## 八、校验脚本要求

`res://scripts/core/validate_data.gd` 需检查：

1. 每个文件的 `id` 与文件名一致
2. 所有**必填字段**存在且类型正确
3. 卡牌的 `multiplier` / `shield_multiplier` 至少要有一个（按 `card_class` 判定）
4. 怪物/卡牌的 `id` 全局唯一
5. 关卡引用的 `monster_pool` / `boss_id` **必须在 monsters 目录中存在**
6. 枚举值在合法范围内
7. 装备的 `slot` 与 `item_class` 匹配

> **收口动作**：专项任务交完数据后，主任务跑一遍校验脚本，零错误才算完成。这是并行开发的质量闸门。
