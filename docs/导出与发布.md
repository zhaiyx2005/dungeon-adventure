# 导出与发布

> 9-26 首次导出 Windows 包时踩到一个**静默失效**：编辑器里一切正常，
> 导出版「所有卡牌不见了」，而且**一条错都不报**。根因与验收手段记在这里。

---

## 一、怎么导出

**编辑器**：项目 → 导出 → 选 `Windows Desktop` 预设 → 导出项目。
预设存在 `export_presets.cfg`（`export_filter="all_resources"`，不带过滤规则）。

**命令行**（等价，适合脚本化）：

```bash
GODOT=D:/100_study/130_game_engine/godot_v4.72/Godot_v4.7.2-stable_win64.exe
"$GODOT" --headless --path . --export-release "Windows Desktop" "导出/地牢冒险记.exe"
```

产物在 **`地牢冒险记开发/导出/`**：

| 文件 | 大小 | 说明 |
|---|---|---|
| `地牢冒险记.exe` | ~104 MB | 双击这个就能玩（引擎已内嵌） |
| `地牢冒险记.pck` | ~43 MB | 全部资源。**必须和 exe 放一起**，删了游戏打不开 |

> 导出耗时约 20 秒，能跑满 100% 就很稳，不必反复导。

---

## 一之二、🔴 「游戏打不开」先查这个：exe 还在不在

**9-28 真实事故**：导出版**丢了**，用户报「无法打开游戏」。

原因不是代码，是**导出目录名**。当时的预设写的是：

```ini
export_path="新建文件夹/地牢冒险记.exe"      # ✗ 危险
```

`新建文件夹` 这个名字看起来就是临时垃圾，139 MB 一坨，**很容易被当垃圾清掉**
（事后在回收站里找到了 `E:\...\地牢冒险记开发\新建文件夹`，删除时间与用户报障时间只差 28 秒）。

**已改为 `导出/地牢冒险记.exe`**，并加进 `.gitignore`。另外：

* 导出产物**只有两个文件**（exe + pck）。它们**不是**临时文件、**不要**放进回收站。
* `地牢冒险记.pck` 是全部资源（数据表 + 贴图 + 音频），**必须与 exe 同目录**。
* 想移动游戏，请**整个 `导出/` 目录一起移动**。

**判断"打不开"是哪一层**：

| 现象 | 原因 |
|---|---|
| 找不到 exe / 双击无反应 | 导出版被删或移动了 → 重新导出（见第一节） |
| 双击闪一下就退 | 缺 `.pck`，或 exe 与 pck 不在同一目录 |
| 窗口开了但卡在开屏 | 开屏页**需要点一下鼠标左键**才进主菜单（原有设计，不是卡死） |
| 进去了但没卡牌 / 没图 / 没声音 | 见第四节「判断是从哪一层坏的」 |

## 二、🔴 导出会**改写资源形态**（这是所有坑的源头）

Godot 导出时默认开启 `editor/export/convert_text_resources_to_binary`，于是：

| 项目里的形态 | 包里的形态 | 运行时怎么解析 |
|---|---|---|
| `data/cards/aegis.tres` | `data/cards/aegis.tres.remap`（存根）<br>+ `.godot/exported/<seed>/export-<md5>-aegis.res` | `load("res://data/cards/aegis.tres")` 跟随 remap ✓ |
| `assets/.../aegis.png` | **只剩** `assets/.../aegis.png.import`<br>真正的贴图在 `.godot/imported/aegis.png-<md5>.ctex` | `.import` 里的 `[remap] path=` 指过去 ✓ |
| `scripts/core/game_data.gd` | `...game_data.gd.remap` + `.gdc` | 同上 ✓ |

**结论：`load()` 永远没问题；只有"扫目录"会出问题。**

## 三、🔴 铁律：不要自己写 `DirAccess` + `ends_with(".tres")`

```gdscript
# ✗ 编辑器里能跑，导出版一张都扫不到，且不报任何错
dir.list_dir_begin()
var f := dir.get_next()
while f != "":
    if f.ends_with(".tres"):        # 导出版这里的 f 是 "aegis.tres.remap"
        load(dir_path + f)
    f = dir.get_next()
```

导出版目录里的条目名是 **`<id>.tres.remap`**，不以 `.tres` 结尾 →
循环体一次都不执行 → `db.cards` 为空 → **整个游戏没有任何卡牌**，
而日志里只有一行正常的 `[GameData] 数据加载完成：卡牌 0 / 怪物 0 / 物品 0 / 关卡 0`。

```gdscript
# ✓ 统一走这个（它会剥掉 .remap / .import 后缀，返回能直接 load 的逻辑路径）
for full_path in GameDatabase.list_data_files("res://data/cards/"):
    var res := load(full_path)
```

> `GameDatabase.normalize_entry()` 是同一套归一化，贴图目录计数也要用它：
> 编辑器里贴图是 `.png` + `.png.import` **两个条目**（不去重会数成两倍），
> 导出版**只有 `.png.import`**（不归一化会数成 0）。

同类写法**已经全部改掉**，以后新增目录扫描一律走 `list_data_files()` / `normalize_entry()`。

## 四、导出版验收（四步，缺一不可）

| 步骤 | 命令 | 看什么 |
|---|---|---|
| **1. 代码侧断言** | `python tools/godot_run.py _t_stage1` | 8 条"目录扫描（导出版 remap 兼容）"断言：归一化规则 + 四个目录的扫描条数 |
| **2. 导出后空跑** | `导出/地牢冒险记.exe --headless --quit-after 200` | `[GameData] 数据加载完成：卡牌 54 / 怪物 26 / 物品 67 / 关卡 5` |
| **3. 包完整性** | `python tools/check_export_pack.py 导出/地牢冒险记.pck` | 188 个 `.import` 的 remap 目标 + 153 个 `.tres` 的存根/落点是否都在包里；并提示"数据资源全是 `.remap`"这一风险 |
| **4. 真实渲染启动** | `导出/地牢冒险记.exe --quit-after 300` | 有窗口、有 `OpenGL API ... Using Device` 行、**无** `SCRIPT ERROR` / 贴图加载失败（headless 用的是 dummy 渲染器，贴图解码路径不同，所以必须再跑一次真渲染） |

> ⚠️ 导出版**不支持 `--script`**（会被忽略，跑的还是主场景），
> 所以 `_probe_export.gd` 那种探针**没法直接在导出版里跑**。
> 想在导出版里做资源体检，只能靠上面第 2/3/4 步（空跑日志 + 解析 `.pck` + 真渲染启动）。

### 判断"卡牌不见了"是从哪一层坏的

| 现象 | 原因层 | 查法 |
|---|---|---|
| 卡牌张数 0 | `GameDatabase` 目录扫描 | 第 1/2 步 |
| 张数对、卡面上是纯色块 | `ArtRegistry` 拿不到贴图 | 第 3 步（贴图 remap 落点） |
| 张数对、图对、但没声音 | 音频 `.import` 落点 | 第 3 步（`.wav.import` 的 `path=`） |

## 五、包里有什么（43 MB 的正常构成）

`.godot/imported/*.ctex`（163 张贴图）+ `*.sample`（16 个音频）+ `*.fontdata`（2 个字体）
+ `.godot/exported/<seed>/*.res`（153 个数据资源）+ `.import`（188 个，**这是贴图解析的必需项，不是垃圾**）
+ `project.binary`。共 848 个条目。

> 别手动删包里的 `.import` —— 贴图就靠它指向 `.ctex`。

### 一个会反复被问的点：`导出/` 目录会不会被自己打进包里？

不会。预设是 `export_filter="all_resources"`，只收**资源**；
`.exe` / `.pck` 不是资源，不会被递归收进去（导出后 pck 从 41.1 MB 涨到 42.7 MB，
增量正好是新增的 8 张背景图，可以确认没有自我包含）。
